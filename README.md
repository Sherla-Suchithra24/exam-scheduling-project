# Exam Scheduling System

A Python-based exam scheduling system that assigns exams to suitable dates, time slots, rooms, and invigilators while checking student conflicts, room capacity, equipment requirements, accommodations, and availability constraints.

## Project Overview

Scheduling exams requires coordinating multiple resources and constraints. This project reads exam and resource information from CSV files, attempts to assign each exam to a valid slot and room, and records exams that could not be scheduled.

The project also includes a validator that checks the generated schedule for relational-integrity issues and selected hard-constraint violations.

## Features

- Reads input data from CSV files in the `data/` directory.
- Considers exam date windows (`earliest_date` and `latest_date`).
- Uses two daily slot start times: `09:00` and `13:00`.
- Checks student conflicts so a student is not assigned to overlapping exams.
- Checks room status, room closures, room capacity, and capacity effective dates.
- Checks required room equipment and accessibility accommodations.
- Accounts for extended-time accommodations when calculating exam duration.
- Checks invigilator availability and overlapping assignments.
- Writes scheduled and unscheduled exam reports.
- Produces audit events, an issue log, and a scheduler summary.
- Provides a separate validation script for checking generated assignments and input-data integrity.

## Input Data

The scheduler uses CSV data describing students, courses, enrollments, exams, exam requirements, rooms, room capacities, invigilators, invigilator availability, accommodations, room equipment, exam equipment, and room closures.

The validator also checks relationships between these tables, including relevant student, course, exam, room, and invigilator identifiers.

Use synthetic or appropriately anonymized data when sharing the repository publicly. Do not commit private student information or other sensitive data.

## Run the Project

### 1. Generate input data (optional)

If you want to generate data using the project's existing data-generation script, run:

```bash
python generate_data.py
```

**Note:** Run this only if you intend to generate or replace the input data. Check the script before running it if you need to preserve existing CSV files.

### 2. Run the scheduler

From the project root:

```bash
python scheduler.py
```

The scheduler writes its schedule, unscheduled-exam list, audit events, issue log, and summary to the `outputs/` directory, as implemented in the script.

### 3. Validate the generated schedule

After the scheduler finishes, run:

```bash
python validator.py
```

The validator prints a JSON summary and writes `outputs/validation_summary.json`. It exits with an error status if validation errors are found.

Run the scheduler before the validator so the validator checks the latest generated output.

## Scheduling Constraints

The current implementation checks or accounts for the following constraints:

- **Exam date window:** an exam must be assigned between its configured earliest and latest dates.
- **Student conflicts:** a student must not have overlapping scheduled exams.
- **Room availability:** rooms must be open and not closed for the exam date.
- **Room capacity:** the room capacity must be effective on the exam date and sufficient for the enrolled students.
- **Equipment and accessibility:** the room must provide the required exam equipment and applicable accessibility accommodations.
- **Exam duration:** the scheduled duration includes the base duration and the applicable extended-time accommodation.
- **Invigilator availability:** the assigned invigilator must be available for the selected date and slot.
- **Resource overlap:** the same room or invigilator must not be assigned to overlapping exams.
- **Schedule reconciliation:** each exam should appear as scheduled or unscheduled, without being assigned more than once or appearing in both lists.

The validator checks the generated assignments against the constraints implemented in `validator.py`. A successful validation means no errors were reported by those checks; it does not prove that the schedule is optimal or that every possible real-world constraint is modeled.

## Output Files

- `final_schedule.csv` — exams assigned to a date, time, room, and invigilator.
- `unscheduled_exams.csv` — exams that could not be assigned, with reason codes.
- `audit_events.csv` — scheduler audit events.
- `issue_log.csv` — logged scheduling issues.
- `scheduler_summary.json` — summary counts and reason codes from the scheduler.
- `validation_summary.json` — validation summary and any reported errors.

The precise columns and event details are defined by the current Python scripts.

## Known Limitations and Future Improvements
